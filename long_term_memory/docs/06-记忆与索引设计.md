# 06 · 记忆与索引设计

> 先读 [00-总览与取舍](00-总览与取舍.md)。
> 当前路线：客观记忆用索引（folders / entries），不使用图存储；
> 情感记忆用 episode 卡，每轮可写或修订，允许空过。
> 图记忆 / PPR / NGM 只作历史与参考，不进入本设计。
>
> 目标：在现有 `[[MEM]]` 流程上增加结构化事件、三级索引和情感记忆；
> 不推翻“每轮追加、压缩前在上下文、压缩后合并”的现有节奏。
> 本文是实现规格；验收条目见第 11 节。

最短路径：

```text
[[EVENT]]   → folders / entries → 三级索引 → assembler
[[EPISODE]] → 工作卡 A/A+/A++ → 候选 0+10（全文暂关）→ USED
[[MEM]]     → 旧会话记忆，保留兼容
```

## 1. 与现有流程的关系

现有流程（`parser.py` / `cli.py` / `store/memory.py` / `compressor.py`）：

```text
模型每轮回复末尾写 [[MEM trigger=… op=append|replace body=…]]
→ parser 解析 mem_ops
→ memory.upsert(session_id, trigger, entries)
→ sync_memory() 把新 trigger 放进 memory_delta
→ 下一轮以【记忆·新增】注入
→ 压缩后 merge_memory() 把全部记忆压成【记忆】trigger:summary
```

保留这套节奏，只增加两类内容：

```text
[[EVENT {json}]]   结构化事件，每轮追加；供索引、检索、约定到期使用
[[EPISODE {json}]] 情感记忆，每轮可写或修订上一张 open 卡；不新建时允许空过
```

`[[MEM]]` 继续保留，作为人读的触发点摘要；不再承担结构化字段。

## 2. 数据模型

### 2.1 event（客观）

```json
{
  "id": "ev_0007",
  "type": "commitment",
  "owner_id": "owner",
  "scope": "qq",
  "title": "下周三和老大吃 KFC",
  "text": "他说下周三去吃 KFC，我说好。",
  "facets": {
    "people": ["person_owner"],
    "places": ["place_kfc"],
    "objects": [],
    "topics": ["kfc", "约定"]
  },
  "occurred_at": "2026-11-05",
  "due_at": "2026-11-05T19:00:00+08:00",
  "due_precision": "day",
  "status": "active",
  "epistemic": "observed",
  "source_turn": 1201,
  "created_at": "2026-10-29T21:40:00+08:00"
}
```

约束：

```text
type        commitment / plan / fact / event / observation / preference / relationship
owner_id    事件归属的用户；群聊按 uid，私聊按 owner
scope       qq / bili / pet / shared；私事不跨平台
epistemic   observed / reported / inferred / uncertain
status      active / done / cancelled / expired / superseded
due_at      只有 commitment / plan 需要
```

`observed` 与 `inferred` 必须分开：「他说不想吃」是 observed，「他好像不太想吃」是 inferred。
`inferred` 不能当成用户明确拒绝。

### 2.2 episode（主观）

```json
{
  "id": "ep_0017",
  "type": "episode",
  "owner_id": "xiaohong",
  "text": "他好像不太想吃，但没说。我感觉他是为了陪我才去的。",
  "core_affect": {"v": 2, "a": 3, "agency": 2, "self_focus": 4},
  "summary": "因‘他好像不太想吃’而有点过意不去，又觉得被陪着",
  "diary": "他好像不太想吃，却还是陪我来了。我有点过意不去，又不想戳破。",
  "anchors": ["胶片相机", "管理员"],
  "source_range": [1201, 1218],
  "revision": 0,
  "status": "open",
  "created_at": "2026-10-29T22:10:00+08:00"
}
```

约束：

```text
只从第一人称文本/心念生成，不从客观事件推断感受
anchors 必须指向客观记忆索引：T1..T7 模板短语，≤120 字；可指向已有或本轮新增 objective
  客观索引是短语；objective 本体是客观描述/评价
删除/改名由后台死代码统一处理；清理 objective 索引与 anchors 引用，不依赖模型，不会悬空
owner_id/scope 字段预留；鉴权暂不实现，读取时按假设的 uid 过滤
scope 默认 owner_only，不进 B站公开块
正文不删；用户要求删除时走后台隔离，不由模型删

版本链：A → A+ → A++ → B → B+ → C
  只允许修改最新 open 卡
  写入 B 后 A 及其修订 sealed，永不再改
  同一卡最多 3 次修订或 6 轮，超限强制新建
  修订 append-only；旧版本只审计，不参与召回

工作卡 vs 库卡：
  A/A+/A++ 是工作卡，不进总库
  不续写或系统强制时，最新 revision 入库并记录 source_epoch
  切断判据：本地不校验四维；是否续写由模型给出的 thread_id 决定；四维只按 1..5 存储。
  封存后只召回最新 sealed revision；A/A+ 只审计
```

### 2.3 folder 与索引

```text
folders(id, parent_id, name, kind)
entry_folders(entry_id, folder_id, weight)
```

固定一级目录（不超过 10 个）：

```text
commitments/   约定、承诺、待办
facts/         稳定事实
events/        发生过的事
observations/  观察与推断
people/        人物
places/        地点
topics/        话题
episodes/      主观体验（不折叠）
```

二级目录按需生成（`commitments/active`、`people/管理员`、`time/2026-11`），不把 tag 直接变成目录。

一条 event 可属于多个目录，正文只存一份。

## 3. 三级可见性

```text
一级（工作集）    当前对话可能用到的，最多 12 条
二级（索引页）    每个目录的标题 + 时间 + 状态，不返回正文
三级（最小索引）  按 id 读一条完整 event / episode，一次最多 3 条
```

提升规则：

```text
触发     新写入 / tag 命中 / 模型 read / 用户明确提到
上限     一级最多 12 条
过期     tag 命中 30 分钟或 5 轮；read 24 小时；新写入 1 小时
降级     超限时按 last_used × weight 淘汰回二级，不删除
```

只改 `level`，不复制正文：

```text
entries(id, owner_id, level, promoted_at, expires_at, promote_reason)
```

## 4. 每轮流程

```text
1. 取用户消息，解析 active_uids（uid 正则 + 白名单）
2. 检索：owner_id ∈ active_uids，scope 允许，status=active
3. 组装：
     system   人格卡（固定前缀）
     user     常驻可变层（【此刻】【关系】【未完成】）
     user     本轮想起（1~2 条 episode 摘要）
     最近窗口 原始对话
     user     用户消息
4. 调用模型一次
5. 解析：
     正文 / 心念 / [[STATE …]] / [[EVENT {json}]] / [[MEM …]]
6. 写库：
     event 追加（幂等键：owner_id + source_turn + type + title）
     state 更新（步长、clamp）
     memory.upsert（兼容 [[MEM]]）
7. 索引：
     新 event 归属 folder，level=2
     tag 命中提升 level=1，设置 expires_at
8. 压缩（按现有触发）：
     只压对话；不生成情感卡；情感卡由每轮 EPISODE 产生
     解析失败只丢卡片，不丢压缩
9. 日终：
     聚合常驻层；状态回落；due_at 复核
```

### 4.1 事件打分（v/a/agency/self_focus 五点定版）

用途：给每一句祀的台词打四点，供 event / episode 的状态层使用。只评这句话本身，不推断内心或后文。

```text
v 效价：1 明显不快 | 2 略不快 | 3 中性 | 4 略愉快 | 5 明显愉快
a 激活（文本特征）：1 平铺直叙 | 2 正常陈述 | 3 反问/感叹/重复 | 4 强断言/连续短句 | 5 爆发式表达
agency 能动性：1 完全无力 | 2 略被动 | 3 有限行动 | 4 主动 | 5 完全掌控
self_focus 自我聚焦：1 完全对外 | 2 略对外 | 3 混合 | 4 略向内 | 5 完全向内
```

交叉积：

```text
a×agency：低a低ag=麻木/认命；高a低ag=焦虑/挣扎；高a高ag=愤怒/行动；低a高ag=冷静掌控
v×self_focus：低v高sf=自责/反刍；低v低sf=对外不满；高v高sf=自豪/被爱；高v低sf=欣赏/连接
```

summary 规则：

```text
≤40 字，写“一级证据 + 感受/评价/行动倾向”
一级证据 = 句中可直接引用的事实/动作/词
不允许只写抽象情绪；也不复述整句
```

diary 规则：

```text
≤120 字，第一人称日记式
写“我当时觉得/我在意/我想做什么”
可有场景细节，但必须由这句话支持；不补后文，不写对方内心
```

## 5. uid 与索引隔离

```text
每个用户一套索引，但共享同一张表，用 owner_id 过滤
uid 匹配用正则/白名单，不用向量
只把“上下文中活跃的群友”拉进本轮索引
```

示例：

```text
active_uids = {owner, uid_12345, uid_67890}
SELECT … WHERE owner_id IN (…) AND status='active'
```

不匹配的 uid 不参与召回，也不进入常驻层。群聊里 500 人不会产生 500 套索引文件。

## 8. 本轮想起

最多 2 条，每条 ≤120 tokens，只给摘要 + 来源 + 类型。

选择：

```text
1. 当前话题 anchor 命中
2. 当前状态与 episode 的 affect 距离
3. 未完成事项
4. 关系事件
```

类型标签用于解释和调参：

```text
mood_congruent  同调
nostalgia       怀旧
attachment      依恋激活
unresolved      未完成
peak            峰值
```

人格过滤优先：与人格卡排除项冲突的记忆直接丢弃。

### 8.1 索引总表的清晰度位（已实现第一版）

索引总表是唯一状态表：**压缩器与调用检查器写，举荐器读**。三者共享这一张表，
任何一方不写位，举荐就会错。

```text
memory_index(target, kind, source_turn, clarity, updated_turn, updated_at)
clarity = clear | fuzzy | forgotten
```

写入者与时机：

```text
记忆落库      MEM / EPISODE 产出 -> 插入或更新该行：clarity=clear, source_turn=turn
压缩器        taken 轮的条目 -> fuzzy；recent 轮 -> clear；rewind 删除的轮 -> forgotten
调用检查器    本轮 memory_read 且折入当前轮的条目 -> clear；未折入的不改位
举荐器        只读，不写
```

读取（举荐器内部，过滤与配额同一函数）：

```text
eligible = 总表中 clarity != clear 的条目
selected = eligible 按 score 取满 quota；不足则少于 quota，不拿 clear 补
output   = 按举荐器规则分配全文/索引（当前 0+10）
```

- 过滤发生在配额之前：池子够时一定取满 10 条，不会被事后剔除成 2 条。
- `fuzzy`、`forgotten` 正常参与打分；`clear` 直接不进入 `eligible`。
- 不足时允许少于配额，这是窗口状态问题，不是去重失败。

三模块闭环：

```text
记忆层     条目落库 + 写索引总表
上下文层   压缩器改 taken/recent 的位；调用检查器改折入项的位
举荐层     读总表 clarity != clear -> 过滤 + 配额 + 排序 + 全文/索引分配
```

第一版未覆盖：

```text
rewind / gone   index_reconcile 已挂在压缩后；/rewind 仍暂未启用，启用时需一并调用
未折入          不改位：source_turn 在窗口仍 clear，已压缩仍 fuzzy（正确行为）
折叠长度        不设单轮上限；由压缩器双阈值与模型输出上限约束
```

轮次定义：**一次用户发信 + 该轮所有工具调用 + 最终回复 = 1 轮**。

```text
系统提示词 + 人格卡 + 置顶/只读索引        固定前缀，永久不变
+ n 条压缩轮
+ m 条非压缩轮（用户信息 + 工具结果 + 回复，已去掉协议壳）
+ 本轮用户信息 + 灵活索引
```

工具结果折叠：**折叠是写入决策，`clear` 是折叠完成后登记的结果**；
不能用 `clear` 反向决定折叠。**上下文是存在度的唯一状态源**；
`memory_access` 之类的外部表只做审计与排序，不参与 clear/fuzzy/forgotten 判定。

折叠判据是「本轮最终回复是否采用了这一条」，不是「是否读过」：

```text
USED 声明（例：客观 4 + 情感 4）
  原文折叠：本轮用户信息 + [memory_read ep_x] 原文 + 模型回复
  上下文标记：[memory_read ep_x]   -> presence = clear

未采用（例：另 8 条）
  不折入；上下文里没有任何痕迹
  presence = forgotten -> 下一轮正常举荐

单轮原文超过硬上限（默认 8000 字符）
  按 USED 顺序折入，单条截断；仍超出的折为 [查过 ep_x] 摘要 -> fuzzy
```

`forgotten` 的再次举荐不是重复噪音，是“忘记后重新想起”的机制；
`clear` 才是抑制举荐的状态。不采用的内容留在上下文里只会占预算，
并错误地把它压成 `clear`、长期退出推荐。

presence 全部由上下文解析得出（不查外部表），标记优先于 source_turn：

```text
窗口内某轮出现 [memory_read target]   -> clear（原文在）
窗口内某轮出现 [查过 target]         -> fuzzy（只有索引）
source_turn 所在轮 = window          -> clear
source_turn 所在轮 = compressed      -> fuzzy（只剩摘要，可能没提到）
source_turn 所在轮 = gone / 缺失      -> forgotten
```
- `USED` 里的 `mem:id` 先归一化为 trigger，再登记。
- 未写 USED 时不折入；这些条目保持原状态，下一轮按原状态举荐。
- 压缩时整轮（用户信息 + 原文折叠 + 回复）一起进压缩轮；该轮变 compressed 后全部降为 fuzzy。
- 不设单轮折叠上限；轮次长度由压缩器双阈值与模型输出上限约束。

## 9. 反刍 / 怀旧 / 被接纳

这些是过程，不是四维状态；判据放本地，不让模型输出「我在反刍」。

### 9.1 反刍判据

```text
rumination_flag =
    v <= 2
    and a >= 2
    and same_topic_streak >= 3
    and self_focus_ratio >= 0.5
    and abstract_why_count >= 2
```

`b` 不参与准入。它是对话行为，独白里只作排序；`i` 也不做门槛，只用于排序。

### 9.2 当前阶段：只给 Δ 结构候选

当前不标 path，不判断“同调/修复/重评”。只算 Δ，按距离和变化数排序，取 3~5 条。

```text
Δv = clamp(cand.v - state.v, -1, +1)
Δa = clamp(cand.a - state.a, -1, +1)
Δagency = clamp(cand.agency - state.agency, -1, +1)
Δself_focus = clamp(cand.self_focus - state.self_focus, -1, +1)
```

每条候选附 Δ、|Δ|、tag、scene。是否属于某条情感路径，等离线/人工标注后再加；本模块不猜。

排序：

```text
score = 0.70 * (1 - distance/12) + 0.30 * (change/4)
```

`distance` 是四维原始距离，`change` 是 Δ 非零的维数。

候选分层（2026-10-30）：

当前 0+10（全文暂关）；恢复全文时按下列分层：

```text
前 3 条全文：反刍 / 转移方向
  允许与当前状态同调，允许负性，用来延续当前情感线
后 7 条索引：非反刍
  优先不同 valence / topic / agency 的方向，提供反向候选
  不要求它们适合继续反刍，只要求能作为跳出当前状态的参考
```

当前实现：0 全文 + 10 索引；Δ 3 条 + tag 命中最多 5 条（不足不补）+ 随机 2 条。恢复全文时的分层仍待落代码。

短时去重（按压缩 epoch，不按固定轮数）：

```text
记忆写入后不立刻进候选；产生它的上下文被压缩后，才允许进入候选
候选被展示后记录 last_shown_epoch；该段上下文压缩后，才允许再次进入候选
select 的 recent_ids 由这两个 epoch 条件派生
工作卡（A/A+/A++）不在库里，不参与推荐去重
```

### 9.3 状态转移

按候选的 Δ 走，每次最多一档：

```text
state.v += sign(Δv) * min(1, |Δv|)
state.a += sign(Δa) * min(1, |Δa|)
state.agency += sign(Δagency) * min(1, |Δagency|)
state.self_focus += sign(Δself_focus) * min(1, |Δself_focus|)
```

不直接跳到候选值。

### 9.4 场景限定

```text
agency 是能动性，不是情绪；独白里仍可用
self_focus 是聚焦对象，不是情绪强度
a 在独白里只是文本代理，置信度低
tag（怀旧/被接纳/未完成）不参与选择
```

### 9.6 用户意图

用对话行为，不分析用户四维：


### 9.7 运行约束与待定项

```text
weight 不衰减。运行时只记录 used / exposed / blocked，离线分析后再调。
总预算不设硬矛盾：当前 0 全文 + 10 索引；恢复全文时 3+7，按可用预算裁索引，再裁 diary。
UID/scope 鉴权暂不实现：owner_id/scope 作为接口字段预留；
  当前按后台死代码绑定 uid 的假设验收。
self_focus：后续提示词工程；按评价对象而非“我”字判定。
v×agency：后续提示词/参数设计；检查相关性，必要时降低 agency 权重。
objective 默认私密；后台手工审核转公开。
B站人物区分（例如此人回复过我）属于验权设计，暂不实现。
USER_STATE 打 v/a/agency/self_focus，复用同一套五分量表客观评估用户情绪；
  只写入 user_state 表作日志，不进入上下文，不参与检索/权重/USED；
  后续由角色卡记录“某情绪下人格倾向如何回应”，当前不接入热路径。
如何应对由人格卡决定，不写死互补规则：
  同一“高a高agency”，可以接住、退半步、反问或划界，取决于人格卡与关系阶段。
四维复用的原因：纯标签太粗，新造维度成本高；直接沿用现有量表，只换用途。
```

### 9.8 无合并基线（2026-10-30）

```text
验收基线：allow_merge=False（tests/acceptance/no_merge_short_test.py）
  → 每轮 EPISODE 独立成卡，不做 revision 合并
  → thread_id 只作标签，不触发本地合并
  → 允许模型输出 [[EPISODE none]]
  → 这是固定验收基线；允许合并模式只作对照
```

实测：

```text
10 封家书 + 4 个无信息短句 → 14 轮 / 14 张卡 / 全部 revision=1
短句“嗯 / 好 / 知道了 / 晚安”仍然生成了卡
```

这些短句卡视为“模型记忆自迭代”：模型从寒暄里补出了“父亲只回一个字，我请他报平安”一类日记。方向接近日记，允许并入主记忆库，不本地过滤。

取舍：

```text
不丢信息：每轮独立，不因合并丢掉阶段差异
代价：卡数增长，候选与存储压力上升；版本链失效
合并模式：省卡、能续写，但可能把不同情感阶段合并成一张
当前：验收基线用 no-merge；代码默认 allow_merge=False（`config.allow_merge`），测试脚本显式 False
```

## 10. 删除与隐私

```text
模型永不删除主观记忆
模型可以提 forget（客观事件），由后台执行

  软删   tombstone + scope 隔离，不再召回
```



## 14. 边界

- 本设计不改变“每轮一次模型调用”的节奏；反刍/意图判断在本地。
- EVENT 是模型回话时追加，不依赖压缩；压缩前它在上下文里，不需要查索引。
- 情感卡每轮可写；压缩只生成剧情摘要，不生成情感卡。
- 索引是派生数据，可重建；events / episodes 是唯一真相。
- 所有阈值是工程初值，需用回放集校准，不声称来自心理学定律。
