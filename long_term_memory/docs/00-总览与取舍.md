# 00 · 长期记忆：当前实现与取舍

> 先读这一页。它说明现在做什么、不做什么、为什么。
> 详细规格见 [06-记忆与索引设计](06-记忆与索引设计.md)；图路线见 [NGM 路线](../NGM路线-长期记忆存取/README.md)。

## 一句话

客观记忆走索引（folders / entries），情感记忆走 episode 卡；
**不使用图存储**。图 / PPR / NGM 只作历史参考，不接当前生产路线。

> 客观记忆基线是 `harness/store/memory.py`（trigger + entries），`harness/cli.py` 在用。
> `harness/long_term.py` 是情感卡 + 新索引实验原型，不是基线。
> 情感→客观连接实现见 [06-记忆与索引设计](06-记忆与索引设计.md) 的“情感→客观连接”。

## 现在是什么

### 客观记忆

- 存储：`folders` / `entries` / `entry_folders`
- 每轮 `[[EVENT]]` 追加；压缩只生成剧情摘要
- 三级：目标为工作集 ≤12 / 目录页 / 按 id 读正文；**当前未实现**（见 06 §3）
- `owner_id` + `scope` 字段预留；鉴权暂不实现

### 情感记忆

- 每轮 `[[EPISODE]]` 工作卡：A / A+ / A++；不续写则入库
- 字段：`v/a/agency/self_focus` + `summary` + `diary` + `anchors`
- 版本链：A → A+ → A++ → B → B+ → C；写 B 后 A 链 sealed
- 候选目标：当前 0 条全文 + 10 条索引（情感卡全文暂关）；`affect_full_count=3` 可回到 3+7。`affect.py` 原型只返回 3~5 条 Δ 候选
- 权重静态，只记 `used / exposed / blocked` 日志，离线调

## 为什么不用图

| 方案 | 问题 | 结论 |
|---|---|---|
| 图记忆 | 需要预先写图、建边、LLM 抽边；维护成本高 | 不作为生产路线 |
| 索引式 | 每轮追加、压缩合并、按 id 读；可控、可解释 | 当前路线 |
| 图 / PPR / NGM | 有实验代码与评测，保留参考 | 历史，不接生产 |

## 关键取舍

| 问题 | 取舍 |
|---|---|
| 每轮情感 vs 压缩情感 | 每轮工作卡；压缩不生成情感卡 |
| 3 全文 vs 纯索引 | 当前 0 全文 + 10 索引；3+7、2+4 由 `affect_full_count` 切换 |
| 去重 vs 反刍 | 按压缩 epoch，只挡全文重复；工作卡不参与 |
| 权重 | 不衰减；只记录 used / exposed / blocked |
| USED | 只记日志，不实时训练 |
| USER_STATE | 复用五分量表评估用户情绪；只写 `user_state` 表作日志，不进入上下文，不参与检索/权重/USED；后续由角色卡决定回应 |
| UID / scope | 鉴权暂不实现；owner_id/scope 字段预留 |
| self_focus | 按评价对象判，待校准 |
| v×agency | 相关性待评估，必要时降权 |
| 情感卡与客观 | 双向锚点；子索引只存 id / 短标题 / kind / role / weight |

## 当前验收基线（2026-10-30，固定）

```text
验收基线：allow_merge=False
每轮 EPISODE 独立成卡；thread_id 只作标签
禁止模型判断合并
允许合并模式只作对照，不参与验收
10 封家书 + 4 个无信息短句 → 14 轮 / 14 卡 / 全部 revision=1
```

短句“嗯 / 好 / 知道了 / 晚安”仍可能生成卡片，视为“模型记忆自迭代”，允许并入主记忆库，不本地过滤。

取舍：

```text
不丢信息：每轮独立，不丢阶段差异
代价：卡数增长，候选/存储压力上升；版本链失效
合并模式：省卡、能续写，但可能把不同情感阶段合并
当前：验收基线用 no-merge；代码默认 allow_merge=False（`config.allow_merge`），脚本显式关闭
```

## 感情记忆接入基线（2026-10-30）

```text
真实对话：30 封家书
```

口径说明（2026-10-30 核对）：这条基线来自 `thirty_letters_test.py`，该脚本每轮
`known_affect_ids.clear()`，所以候选数会从 0 递增到 10。生产循环不清空，只有压缩后
`merge_memory()` 才复用；`no_merge_report.json`（不清空）里 14 轮候选恒为 1。
两种口径都保留，但“推荐器工作良好”不适用于生产口径下的候选数量。
去重、索引与展开原文的策略待重新设计，见待办 P0。

## 情感→客观连接验收基线（2026-10-30）

原则：连对优先。情感卡可以只引用部分相关 MEM；缺引用不算失败；错绑、格式错误才算失败。

```text

```

结果：

```text

body 至少一条 ≥20 字
bind 1 / 1 / 2

missing = 0
invalid = 0
```

连续两轮缺 MEM：20 轮真实对话从未发生；离线模拟通过。此条不把“自然触发”当作验收条件。

## 锚点失败回退（2026-10-30）

缺行（EPISODE 没有 anchors）和格式错误（不匹配 T1..T7、未命中 objective）走同一套三级回退，
不丢卡、不默认丢弃：

```text
1. 本轮结束发现 → 只记状态；下一轮上下文列出待补卡与缺失项，
   要求模型用 [[ANCHOR ep_xxxxxxxx T1:…]] 补交（不新开 API 轮，省 token）
2. 下一轮仍未补上 → 才发一次补行请求（repair_anchor_protocol）
3. 补行后仍失败 → 写入 memory_faults（现场原文 + 轮次 + 原因），停止自动重试
   人工：python -m harness.lt_cli faults --state failed
         python -m harness.lt_cli set-anchors ep_xxx "T1:…"
         python -m harness.lt_cli delete ep_xxx --soft
```

实现落点：`bind_anchors` 给无 anchors 的卡写 `anchor=''` 哨兵；
`pending_links()` 跨轮返回未绑定项；`anchor_actions()` 分出 fresh / repair / failed。


## 统一 memory_read 与双维度基线（2026-10-30）

```text
入口：memory_read(target)
target：
  ep_…       情感卡
  mem:id     客观 MemoryDB
  T1..T7:…   客观 trigger
```

原则：

```text
情感记忆索引与客观记忆索引是两个维度；
与当前话题相关时，两边都必须各自检索，不能只展开一边。
```

客观候选显示：

```text
[未展开]mem:1 T4:帝江号+舰桥+旧海图
```

实测：

```text
第一轮预填 4 张情感卡 + 6 条客观记忆
同一轮 memory_read 8 次：
  ep_… ×4
  mem:1 / mem:2 / mem:3 / mem:6 ×4
parallel = True
```

入口：

```text
modules/shi_harness/tests/acceptance/prefill_parallel_test.py
test-data/客观事实-自定义/runs/prefill_parallel_report.json
modules/shi_harness/tests/acceptance/test_prefill_parallel_report.py
```

## 候选分层

当前情感卡全文暂关（0 全文 + 10 索引），本节是恢复全文后的设计约束：

```text
前 3 条全文：反刍 / 转移方向
  允许与当前状态同调，允许负性
后 7 条索引：非反刍
  优先不同 valence / topic / agency，作为跳出当前状态的参考
```

当前实现仍让 7 条索引走同一排序；分层是设计约束，尚未落代码。
