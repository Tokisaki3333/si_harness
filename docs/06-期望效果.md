# 期望效果

这份文档写“跑起来应该看到什么”，用于验收和交接。参数、协议细节见同目录其余文档。

## 1. 每轮输出形状

模型每轮回复固定四段：

```text
【心念】想留。可先开口就输了。——手心有点潮。
【正文】
（她别过头，把笔搁下）……走吧。
[[STATE affection=+1 trust=+0 mood=平静 loc=帝江号·舷窗前 exit=0]]
[[MEM none]]
```

- 心念：30 字以内，第一人称碎片，写动机、顾虑或身体反应；
- 正文：动作 + 台词，格式随用户示例；
- 状态行：每轮末尾，`loc` 必写，`exit=0` 默认；
- 记忆行：`[[MEM none]]` 或 `[[MEM trigger=… op=append body=…]]`。

CLI 只展示正文；心念和协议行剥离，但完整内容留在 `assistant` 消息里，下一轮模型能看到。

## 2. 心念的样子

期望：

```text
【心念】两小时没吐几个字，这会儿倒郑重起来了，呆货。
【心念】说抱就抱，当我是暖炉么……可这声气，倒不像闹着玩。
【心念】茶凉了。他刚才那句话……算了，不想了。
```

不期望：

```text
【心念】她其实不想让他走，但嘴上不饶人。          ← 第三人称旁白
【心念】我想说“你别走”，但我不能。                 ← 台词预演
【心念】我的动机是……，顾虑是……，所以我决定……   ← 分析总结
```

判断标准：

- 像不像一个人在碎碎念，而不是在写人物小传；
- 有没有跑题、想错、自欺、重复；
- 正文有没有被心念提前说掉。

## 3. 状态行与缺失策略

正常：

```text
[[STATE affection=+1 trust=+0 mood=平静 loc=帝江号·舰桥 exit=0]]
```

- 每轮末尾；
- 增量 `-15..+15`；
- CLOSE / INTENSE 轮追加 `intensity=+3`；
- `loc=` 由模型按场景修改，外部据此更新场景。

缺失：

- 本轮缺：不立刻进入补行轮，但在下一轮请求中明确要求模型补上缺失行；
- 下一轮补上：计数归零；
- 下一轮仍缺：进入补行轮分支，追加一次补行请求；
- 补行成功：计数归零；
- 补行仍失败：记录 fault，后续按普通缺失继续。

期望效果：缺失后下一轮就要求补行；只有下轮仍不补才进入补行轮分支，补的时候数值平滑。

## 4. 场景

```text
【场景】帝江号·舰桥；已相处约2小时10分
```

- 地点来自上一轮状态行的 `loc=`；
- 时间由外部按轮次推进；
- 场景变化时模型必须写 `loc=`，否则地点不变。

## 5. 记忆

- 快照：`【记忆·已有】…`，进固定前缀；
- 增量：`【记忆·新增】…`，在末尾；
- 新条写入后，压缩时并入快照；
- 记忆按触发点组织，模型应复用已有触发点，而不是每次新建。

期望：模型在相关话题上能想起旧约定，而不是复述一遍设定。

## 6. 压缩

触发：`fixed + 窗口 + 摘要 > context_limit`。

期望看到：

```text
[压缩] 上下文≈340000 tok | 未压缩 40 轮 | 已压缩 120 轮 | 摘要 24 条/2800 tok | 本轮压掉 40 轮
[压缩请求] prompt=… hit=… out=…
```

- `keep` 先满足 `recent_turns_min`，再继续到 `recent_tokens_max`；
- `taken` 是更早的、未压缩过的轮次，一次请求压完；
- API 返回每轮一条摘要；
- 摘要写入对应原文行的 `summary` 列；
- 活动摘要按 token 上限从最久远开始丢弃，保底 `summary_min_items` 条；
- API 失败抛 `CompressError`，不本地回退，提示 `/compress` 手动重试。

期望摘要：

```text
[轮12] - 帝江号·舰桥：管理员带祀前往，祀嘴上嫌弃仍跟着走
[轮13] - 祀在舰桥看星野，问能停留多久
[轮14] - 管理员提到下周三去北边裂隙
```

## 7. 缓存

期望命中率：

| 场景 | 命中率 |
|---|---|
| 普通轮 | 85–92% |
| 压缩后第一轮 | 50–70% |
| 补行轮 | 70–80% |

- 固定前缀（system + 卡 + 快照）不动；
- 摘要、窗口、场景、状态、记忆增量都在后段；
- `/unlock` 不改 system，只改状态机里的 `unlock=` 字段。

## 8. 重启恢复

`/reload` 或启动时自动恢复：

```text
max_turn: 9
window: [1, 2, 3, …]
summaries: 0
state: 【状态机】state=DAILY；affection=69；trust=62；mood=平静；unlock=0
```

- 窗口只恢复未压缩轮次；
- 摘要从 `summary` 列读；
- 状态从最近快照恢复；
- `turn` 从数据库 `MAX(turn)` 续，不从 1 重来。

## 9. 交接验收清单

- [ ] `python -m harness.cli` 能启动，余额查询成功；
- [ ] 第一轮回复含 `【心念】`、`【正文】`、`[[STATE]]`、`[[MEM]]`；
- [ ] CLI 展示时看不到 `【心念】` 和协议行；
- [ ] 下一轮请求里能看到上一轮的 `【心念】`；
- [ ] 本轮缺状态行时，下一轮请求明确要求补行；若下一轮仍缺，才进入补行轮分支；
- [ ] `loc=` 变化后，下一轮场景行跟着变；
- [ ] `/compress` 能手动压缩，失败时打印原因；
- [ ] `/reload` 能恢复窗口、摘要、状态；
- [ ] 普通轮命中率 ≥ 85%。

## 10. 不期望的效果

- 心念变成第三人称总结或台词预演；
- 每轮都写“深刻内心”，正文变短；
- 状态行每轮都缺，靠补行兜底；
- 压缩后摘要重复、乱序、没有轮次号；
- API 失败后静默用本地抽取顶替；
- `/unlock` 改 system，导致整段前缀失效。
